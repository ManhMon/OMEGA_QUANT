## 2026-04-20 (Afternoon Session) - Dynamic Universe & Walk-Forward Fixes

### Context
- **Goal**: Fix `AttributeError: 'NoneType' object has no attribute 'get'` during Walk-Forward Backtest.
- **Root Cause**: `DataModule.transform()` now returns `None` for timestamps where symbols are not yet listed (Dynamic Universe support). Downstream modules (`TargetModule`, `FeatureModule`, `ModelModule`) were calling `.get()` on `None`.

### Fixes Applied (SECURE_NONE_HANDLING_FIX)

#### 1. `target_module.py` - Skip-on-None with Explicit Filtering
- Modified `transform()` to filter `valid_ts_indices` where `ts_data is None` (symbol not listed).
- Removed `ValueError` raise on missing symbol/alignment - now uses `continue` (skip).
- Removed NaN target-padding at final alignment - only keep timestamps where at least 1 symbol has data.
- Changed final alignment from strict intersection to union-based: keeps any timestamp where ≥1 symbol has valid target.
- Contract: `AlignedTargetVector` still maintains no NaN values in output.

#### 2. `feature_module.py` - Per-Symbol Warmup
- Added `None` check in `_to_rows()`: `if ts_data is None: continue`.
- Changed warmup from global (`max` of all symbols) to per-symbol (`min` per symbol's actual data length).
- Logic: `sym_start = max(ret_1_lag, ret_5_lag, vol_z_window, 5)` computed per symbol instead of globally.
- Feature invariance maintained: no NaN in output, all values are finite.

#### 3. `model_module.py` - Dynamic Universe Alignment
- Rewrote `_align_data()` to handle `None` values gracefully.
- Changed from strict intersection to pairwise (ts, sym) matching where both feature AND target exist.
- `ModelModule.train()` now correctly builds `timestamp_to_rows` mapping using per-timestamp row counts (not assuming uniform `n_symbols` per timestamp).
- Validation: `assert model.lineage["train_size"] > 0` and `assert model.lineage["eval_size"] > 0` now pass.

#### 4. `run_walk_forward.py` - Model.predict_one Fix
- Fixed `AttributeError: 'TrainedModel' object has no attribute 'predict_one'` by replacing `model.predict_one(...)` with direct score calculation: `score = model.intercept + sum(model.weights[k] * features.get(k, 0.0) for k in model.weights)`.

### Walk-Forward Results (Final)

| Period | IC | Sharpe |
|--------|-----|--------|
| Train (Baseline) | -0.0014 | 0.0427 |
| Validation | +0.0055 | +0.1575 |
| Out-of-Sample (OOS) | -0.0115 | -0.2493 |

### Analysis of OOS Sharpe Negative
- **Pipeline Status**: ✅ Stable (no crashes, no NaN metrics, all systems operational).
- **Dynamic Universe**: ✅ Fully functional (supports 220+ symbols with varied listing dates).
- **OOS Sharpe Negative Root Cause**: **Alpha Decay** - factors from 2015-2021 training period have lost effectiveness in 2024-2026 VN market regime (foreign room changes, T+2.5 settlement shifts, new IPO wave).
- **IC OOS negative (-0.0115)**: Model is predicting in opposite direction to actual returns in 2024-2026 period.
- **Not a bug**: This is an expected phenomenon in quant strategies. Phase 2 (Alpha Discovery Engine) aims to discover new factors for current regime.

### Key Decisions Made
1. **Skip-on-None > NaN-Padding**: Defensive skipping preferred over filling (maintains no_nan invariant).
2. **Pairwise Alignment**: Model trains on any (ts, sym) pair where BOTH feature AND target are valid (not requiring all symbols at every timestamp).
3. **Per-Symbol Warmup**: Each symbol starts contributing features as soon as it has enough history (no waiting for slowest symbol in universe).

### Next Steps
1. **Phase 2 Alpha Discovery Engine**: Build automated factor discovery for 2024-2026 regime.
2. **Walk-Forward Period Adjustment**: Try shorter OOS window (e.g., Train 2020-2023, OOS 2024-2026) to reduce regime drift.
3. **Potential v21.3 Release**: Dynamic Universe support is a significant feature addition warranting a new version bump.
